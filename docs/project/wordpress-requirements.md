# الزامات قطعی توسعهٔ وردپرس elinstyle

تاریخ ثبت: 2026-11-14. این تصمیم‌های جدید کاربر بر عبارت‌های قدیمی «ویرایشگر انتخاب نشده» و «توسعهٔ وردپرس مجاز نیست» مقدم‌اند.

## ترتیب و دامنه

- توسعهٔ نسخهٔ وردپرس اکنون مجاز است. ابتدا نسخهٔ گوتنبرگ؛ نسخهٔ المنتور تنها پس از تأیید صریح نسخهٔ گوتنبرگ توسط کاربر آغاز شود.
- مبنا نسخهٔ جاری استاتیک در `D:\programming\ChatGPTdev\elinstyle` است؛ این پوشه حفظ شود. خروجی وردپرس در `D:\programming\ChatGPTdev\elinstyle-wordpress` قرار گیرد.
- پنج صفحهٔ موجود، پاپ‌آپ راهنمای اندازه و انیمیشن‌های سبک مبنای تبدیل‌اند. صفحهٔ تازه بدون مأموریت مستقل طراحی نشود.
- ظاهر، فونت محلی یکان‌بخ، RTL، واکنش‌گرایی، توکن‌ها و رفتارهای تأییدشده حفظ شوند.

## استاندارد و سازگاری

- حداقل PHP قالب و هر افزونهٔ اختصاصی: 7.4؛ استفاده از syntax یا API مخصوص PHP 8 بدون جایگزین ممنوع است.
- سازگاری ادعاشده باید با نسخه‌های دقیق PHP، WordPress و WooCommerce در ماتریس آزمون ثبت شود. سازگاری کد قالب با 7.4 با سازگاری کل مجموعهٔ افزونه‌ها یکی نیست.
- استانداردهای کدنویسی و APIهای رسمی WordPress، enqueue استاندارد، ترجمه‌پذیری، escaping متناسب، اعتبارسنجی ورودی و کنترل دسترسی رعایت شوند.
- منطق ماندگار و ویجت/بلوک کاربردی اختصاصی در افزونهٔ همراه قرار گیرد؛ هسته یا افزونهٔ ثالث ویرایش نشود.
- برای افزونهٔ اختصاصی: `Author: Iman Shadmehri` و `Author URI: https://elinweb.ir`؛ در Composer و مستندات نیز همین هویت حفظ شود. لایسنس مستقلاً تعیین شود و از پروژهٔ دیگر کپی نشود.

## گوتنبرگ

- صفحات واقعاً قابل ویرایش با بلوک‌ها و الگوها باشند؛ قراردادن کل صفحه در یک بلوک HTML یا تصویر، جایگزین پیاده‌سازی گوتنبرگ نیست.
- اول از بلوک‌های هسته و قابلیت‌های موجود استفاده شود. بلوک اختصاصی تنها برای نیاز واقعی با ثبت علت ساخته شود.
- توکن‌ها، فونت، رنگ، فاصله، عرض محتوا و CSS بخش‌های صفحه بین فرانت و بوم ویرایش مشترک باشند؛ از theme.json و APIهای رسمی استایل ویرایشگر استفاده شود.
- CSS مشترک در بوم گوتنبرگ، از جمله حالت iframe، بارگذاری شود؛ selectorها طوری محدود شوند که نوارابزار و رابط مدیریت را تغییر ندهند.
- ظاهر صفحات در ویرایشگر و فرانت به‌صورت تصویری مقایسه شود. اسکریپت تعاملی فرانت نباید کنترل‌های ویرایشگر را مختل کند.
- داده‌های فروشگاه از WooCommerce خوانده شوند؛ fallback روشن هنگام غیرفعال بودن آن در نظر گرفته شود. عملیات خرید و ارسال فرم با پیام نمایشی موفقیت جایگزین نشوند.

## المنتور؛ مرحلهٔ دوم پس از تأیید

- دموی مستقل قابل ویرایش با Elementor و Elementor Pro؛ استفاده از ویجت‌های کلاسیک/غیراتمیک طبق خواستهٔ کاربر.
- از ویجت‌های موجود Elementor Pro استفاده شود و ویجت اختصاصی فقط برای کمبود واقعی ساخته شود؛ وابستگی و علت آن مستند شود.
- نصب و آزمایش Pro با نسخهٔ مجاز در دسترس انجام شود؛ فایل یا مجوز آن به‌صورت خودسرانه داخل بسته بازتوزیع نشود.
- نگاشت بخش‌ها، قالب‌های دمو، نسخه‌های آزمایش‌شده و استایل‌های مشترک مستند شوند. این مرحله اکنون مجوز اجرا ندارد.
